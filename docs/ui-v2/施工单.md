## 1. 三层架构（职责切干净，别互相污染）

```
tfd_app/ui2/screen.py   视图层：只按状态绘制，登记热区（HOT）。不含业务、不调引擎。
tfd_app/app_ui.py       外壳层：窗口/事件/线程/状态机/弹窗。唯一的业务编排者。
tfd_app/engine.py       引擎层：现成，不动。
```

**为什么这么切**：视图层是老板逐轮定稿的产物（外观一个字不能变），
一旦把业务塞进去，以后改外观就会碰到业务代码。热区用「登记制」而不是
在外壳里重算坐标——避免布局知识被复制两份（改一处忘一处）。

## 3. 二维码浮层（老板本轮点名）

- **鼠标移上去**就出现，**移开**自动收起（`<Enter>` / `<Leave>`）
- **点一下**钉住（再点一次或点别处收起），方便用手机扫
- 实现：无边框 `Toplevel`（`overrideredirect(True)`），锚定在入口项上方，
  内容 = 二维码图 + 一行说明（微信 ID / 公众号 ID）
- 🔴 **禁止静默降级**：图不存在时，浮层里明确显示「二维码待配置」+ 既有文字信息，
  并在启动日志里记一条。不许出现「点了没反应」。
